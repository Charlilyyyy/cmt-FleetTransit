# Product Discovery

This folder holds CMT Fleet Transit discovery work: validating that the product solves a real, painful problem worth building.

## Purpose

Before architecture, database design, or application code, we document:

1. **The problem** — who experiences pain, what breaks today, and why the timing matters
2. **The people** — personas across operator and family sides of the trip
3. **The gaps** — manual routing, blind spots on the road, communication failures
4. **The bar for v1** — a concrete school-bus scenario that proves value
5. **What we assume** — and what could invalidate the bet
6. **The decision** — proceed to research or stop

## Reading Order

Start with the problem statement, then personas and pain points. Success criteria and assumptions set scope for validation. Finish with the one-pager for a single-page summary and decision record.
